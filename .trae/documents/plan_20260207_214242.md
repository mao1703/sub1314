Vercel 部署报错 "No entrypoint found" 是因为项目根目录下没有 Vercel 期望的构建配置或入口文件。

**问题分析：**
1.  **现有 `vercel.json` 配置错误**：当前的 `vercel.json` 只有 `{"rewrites":[{"source":"/(.*)","destination":"/index.html"}]}`。这通常是用于单页应用（SPA）的配置，且假定 `index.html` 在根目录。但实际上，前端代码在 `client` 目录下。
2.  **项目结构**：这是一个前后端分离的项目（Frontend in `client/`, Backend in `src/`）。
    *   **Frontend**: Vite React App (`client/`)。
    *   **Backend**: Express App (`src/app.js`)。
3.  **Vercel 部署策略**：
    *   Vercel 主要是为前端设计的，但也支持 Serverless Functions。
    *   要在一个 Vercel 项目中同时部署前后端，我们需要配置 `vercel.json` 将请求路由到正确的地方。
    *   **后端**：需要将 Express 应用转换为 Vercel Serverless Function。通常做法是创建一个 `api/index.js` 作为入口。
    *   **前端**：需要指定构建命令和输出目录。

**解决方案：**

1.  **创建 `api/index.js`**：作为后端入口，适配 Vercel 的 Serverless 环境。
2.  **修改 `vercel.json`**：
    *   配置 `builds`（或使用 `rewrites` 配合 Vercel 的自动检测，但手动配置更稳妥）。
    *   将 `/api/*` 的请求转发到后端。
    *   将其他请求转发到前端。
3.  **修改 `package.json`**：在根目录添加 `vercel-build` 脚本（如果需要），或者确保 Vercel 控制台配置正确。
4.  **重要调整**：Vercel Serverless 不支持 `app.listen` 长时间监听端口。我们需要修改 `src/app.js` 确保它导出 `app` 实例，并且只在非 Vercel 环境下调用 `listen`。

**计划步骤：**

1.  **修改 `src/app.js`**：确保 `module.exports = app`，并且 `app.listen` 被条件包裹（例如 `if (require.main === module)`），这在之前的代码审计中已经确认是这样的，所以不需要大改，只需确认。
2.  **创建 `api/index.js`**：
    ```javascript
    const app = require('../src/app');
    module.exports = app;
    ```
3.  **更新 `vercel.json`**：
    ```json
    {
      "version": 2,
      "rewrites": [
        { "source": "/api/(.*)", "destination": "/api/index.js" },
        { "source": "/(.*)", "destination": "/client/dist/$1" }
      ],
       "buildCommand": "cd client && npm install && npm run build",
       "outputDirectory": "client/dist"
    }
    ```
    *Wait, Vercel handling of monorepos can be tricky.*
    *Better approach for Vercel Monorepo:*
    *   **Backend**: `api` folder is automatically treated as serverless functions.
    *   **Frontend**: We need to tell Vercel that the "Root Directory" for the frontend is `client` **OR** we configure the root `package.json` to build the client into a specific folder and serve it.

    *   **更稳妥的方案 (Root as Base)**:
        *   根目录 `package.json` 添加 `"build": "cd client && npm install && npm run build"`。
        *   `vercel.json`:
            ```json
            {
              "version": 2,
              "builds": [
                {
                  "src": "api/index.js",
                  "use": "@vercel/node"
                },
                {
                  "src": "client/package.json",
                  "use": "@vercel/static-build",
                  "config": { "distDir": "dist" }
                }
              ],
              "routes": [
                { "src": "/api/(.*)", "dest": "/api/index.js" },
                { "src": "/(.*)", "dest": "/client/$1" }
              ]
            }
            ```
        *   注意：`builds` 配置在 Vercel 2.0 中虽然是遗留配置，但对于这种非标准结构的 monorepo 仍然有效且清晰。或者使用 `rewrites` + `functions`。

    *   **简化方案 (推荐)**:
        1.  创建 `api/index.js` 引用 `src/app.js`。
        2.  更新 `vercel.json` 使用 `rewrites`。
        3.  配置 Vercel 项目设置：
            *   **Build Command**: `cd client && npm install && npm run build`
            *   **Output Directory**: `client/dist`
            *   **Install Command**: `npm install && cd client && npm install` (Root installs backend deps, client installs frontend deps).
