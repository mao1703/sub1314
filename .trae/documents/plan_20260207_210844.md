用户希望在前端展示后端数据库中用户以前提交的标签。
这通常意味着在用户在 `Write.tsx` 页面进行输入时，应该能看到或选择之前的标签（自动补全或推荐列表）。

**回顾与分析：**
1.  **之前移除了推荐功能**：用户最开始要求“清除这个功能的所有逻辑相关代码，实现单纯的展示”，所以我移除了 `availableTags`、下拉推荐列表以及相关的 API 调用。
2.  **现在要求展示**：用户现在明确要求“后端数据库已经有用户以前提交的标签，请在前端展示”。这实际上是要求**恢复并优化**之前移除的推荐功能。
3.  **选中元素**：用户选中的是标签输入框的 `div`。

**需求拆解：**
1.  **恢复数据获取**：在组件加载时（`useEffect`），调用 `api.get('/users/tags')` 获取用户历史标签，并存储在状态中（如 `availableTags`）。
2.  **恢复推荐 UI**：
    *   当用户聚焦输入框或输入内容时，展示一个下拉列表或在输入框下方展示推荐标签。
    *   或者，直接在输入框下方展示“常用标签”区域（如果用户不想用复杂的下拉）。
    *   考虑到之前的下拉列表逻辑比较完整，恢复它是最合理的。但是要确保**简单化**，不要引入之前那种复杂的“从推荐列表删除”逻辑（除非用户明确需要），因为用户之前嫌烦。
    *   不过，用户说“前端展示”，可能只是想在输入框下面列出所有可用标签供点击选择。
    *   结合输入框的交互习惯，**下拉自动补全**是最标准的体验。

**计划步骤：**

1.  **添加状态**：
    *   `availableTags`: `string[]`，存储从后端获取的历史标签。
    *   `showTagDropdown`: `boolean`，控制下拉显示。

2.  **获取数据**：
    *   在 `useEffect` 中调用 `api.get('/users/tags')`。

3.  **渲染推荐列表**：
    *   在输入框下方渲染一个 `ul` 列表。
    *   过滤逻辑：`availableTags.filter(t => !tags.includes(t) && t.includes(tagInput))`。
    *   点击列表项时调用 `handleAddTag`。

4.  **交互优化**：
    *   输入框聚焦时显示下拉（如果有历史标签）。
    *   点击外部关闭下拉（或者简单的 `onBlur` 延迟关闭）。
